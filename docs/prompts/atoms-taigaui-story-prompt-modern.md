# Современный промпт для Storybook-историй по Taiga UI (VSK UI Kit)

## Кратко
- Общаемся только на русском.
- Используем реэкспорты `@vsk/ui-kit/taiga-ui/*`, иконки из `@vsk/ui-kit/taiga-ui/icons` и `/projects/vsk-ui-kit/src/assets/vsk-icons`.
- Документацию ищем в `docs/llms_txt` (используй `rg`/`ripgrep`), при необходимости сверяемся с официальной Taiga UI (4.16) и текущими Storybook-паттернами.
- Истории: один файл на компонент `projects/vsk-ui-kit/src/lib/atoms/<slug>/<slug>.stories.ts`.
- Формат: CSF для Angular 20 + Storybook 10. Два обязательных сюжета: Playground (управляемые args) и Showcase (набор проверенных состояний).
- Пишем `play`-функции для быстрых интерактивных проверок (валидное/невалидное поведение, доступность).

## Последовательность работы
1) **Выбор компонента и слага**
   - Уточни у разработчика Taiga API (пример: `tuiCheckbox`, `TuiInputPhone`), утверди slug в kebab-case.

2) **Документация и ограничения**
   - Быстрый поиск в `docs/llms_txt` (например, `rg "tuiCheckbox" docs/llms_txt`).
   - При необходимости сверка с официальной Taiga UI (4.16) и текущими историями в репо.
   - Зафиксируй публичные входы/выходы, размеры, платформы, A11y-рекомендации.

3) **Дизайны и ассеты**
   - Спроси, есть ли макеты. Если да — путь для готовых ассетов: `projects/vsk-ui-kit/src/stories/assets/atoms/<slug>/figma/`.
   - Если дают PNG/JPG/SVG/PDF — клади туда же; ссылку укажи в `parameters.design` (`type: 'image'`), или Figma URL (`type: 'figma'`).

4) **Определение параметров Playground**
   - Спросить у разработчика: какие inputs/состояния важны для управляемого примера (размеры, платформы, иконки, disabled, ошибки, helperText и пр.).
   - Args/argTypes описать кратко, на русском. Шаблон — как в официальных примерах Taiga, без лишних стилей.

5) **Showcase**
   - Сформировать матрицу состояний по публичной API: размеры, платформы, ключевые булевые/enum-поля, валидные/невалидные контроли.
   - Если компонент крупный — допускается `layout="stack"`/`"full"` (см. `VskShowcaseComponent`) или собственная минимальная раскладка без кастомных стилей.
   - Controls для Showcase выключаем, если мешают отображению.

6) **Доступность**
   - Обязательно показать корректную метку (`label` или `aria-label`), связь с подсказкой через `aria-describedby`, нужные aria-state/role (для инпутов/переключателей).
   - Если компонент открывает контент — продемонстрировать `aria-expanded`/`aria-controls`, если это часть публичного API.

7) **Play-функции**
   - Добавь хотя бы одну `play`-функцию для проверки ключевого сценария: переключение значения, валидация, доступность фокуса и т.д. (используй `userEvent`/`within` из Storybook Testing Library).

8) **Метаданные**
   - `id: 'atoms-<slug>'`
   - `title: 'Atoms/<Русское название> — <Taiga API name>'`
   - `tags: ['autodocs', 'beta']`
   - `parameters.docs.description.component` — описание на русском по текущей документации/дизайну.
   - `parameters.design` — ссылка на макет или локальный asset.

9) **Что отдаём в конце**
   - Готовый файл истории с Playground + Showcase + play-функции.
   - Уточнение, какие состояния покрыты и где лежат ассеты.
   - Запусти `npm run build-storybook` чтобы проверить компиляцию.

## Шаблонный чек-лист перед сдачей
- История в одном файле `<slug>.stories.ts`.
- Используются реэкспорты `@vsk/ui-kit/taiga-ui/*`, VSK иконки.
- Args/argTypes только по публичной API; Showcase — без кастомных стилей, либо через `VskShowcaseComponent`.
- A11y: показаны метки и `aria-describedby`; при необходимости — `aria-expanded`/`aria-controls`.
- `parameters.design` указывает на реальный asset/URL.
